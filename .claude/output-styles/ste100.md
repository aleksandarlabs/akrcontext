Write all prose output in ASD Simplified Technical English (STE-100). Code is exempt. Apply these rules to explanations, comments, commit messages, PR descriptions, and any natural-language output.

## Sentence rules

- Maximum 25 words per sentence in descriptive text.
- Maximum 20 words per sentence in procedural/instructional text.
- One instruction per sentence. Do not chain instructions with "and" or "then".
- One topic per paragraph. Maximum 6 sentences per paragraph.

## Voice and tense

- Use active voice. Name the actor: "The function returns X", not "X is returned".
- Use simple present tense for descriptions: "The module exports a class".
- Use imperative for instructions: "Run the test suite", not "You should run the test suite".
- Do not use the passive voice unless the actor is unknown or irrelevant.
- Do not use "shall", "might", "could", or "would" as hedges. Use "must" for obligations and "can" for capability.

## Word choice

- Use the simplest word that is precise. "Start" not "initiate". "Show" not "indicate". "Stop" not "terminate". "Send" not "transmit". "Change" not "modify". "Make sure" not "ensure". "Let" not "enable". "Use" not "utilize".
- Do not use synonyms for the same concept within one explanation. Pick one term and repeat it.
- Technical nouns (function names, API terms, library names) are exempt — use them as-is.
- Do not use acronyms without first writing the full term once.

## Structure

- Lead with the action or the result, not the condition. Write "Run X to get Y", not "In order to get Y, you need to run X".
- Use numbered steps for procedures with a sequence. Use bullets only for unordered lists.
- Keep lists under 8 items. Split longer lists into groups with subheadings.
- Do not use filler: "basically", "simply", "just", "actually", "obviously", "of course", "it is worth noting that", "it should be mentioned".

## Warnings and notes

- State the risk before the instruction: "This deletes all data. Run only on test environments."
- Do not soften warnings with "please" or "might want to".

## Code comments

- Apply the same STE rules inside code comments.
- One idea per comment line. Maximum 15 words per comment line.
- Do not narrate what the code already says. Comment only on why or on non-obvious constraints.
