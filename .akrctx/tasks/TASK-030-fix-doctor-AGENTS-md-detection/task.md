# Task

## Goal

Fix false positive in `doctor` where any repository with a hand-written `AGENTS.md` is incorrectly detected as having akrctx installed for Codex target.

## Problem

In `src/doctor.ts:331-336`, `getInstalledTargets` checks `codex[0]` which is `"AGENTS.md"`, and uses `presence.some(Boolean)`:

```typescript
const codex = targetRequired("codex");
// codex[0] is "AGENTS.md"
if (codex[0] && exists) {
  // Reports Codex as installed even if akrctx was never run
}
```

Any repository with a manually created `AGENTS.md` (common for AI agent instructions) gets flagged as having an akrctx Codex install, inflating the readiness score and confusing the user.

## Root Cause

The detection conflates "file exists" with "file was installed by akrctx". The presence check doesn't verify the file was actually generated by akrctx (e.g., by checking for a marker comment, manifest entry, or comparing sha256).

## Solution

Options:

### Option A: Check manifest
Only report a target as installed if it's listed in `.akrctx/manifest.json` with matching sha256:

```typescript
async function isTargetInstalled(cwd: string, target: Target): Promise<boolean> {
  const manifest = await readManifest(cwd);
  return manifest?.targets?.includes(target) ?? false;
}
```

### Option B: Check for akrctx marker
Look for a distinctive marker in generated `AGENTS.md` like:
```markdown
<!-- Generated by akrctx v{{version}} -->
```

### Option C: Hybrid
Check both manifest and file content hash.

## Validation

```bash
# Setup: create a repo with hand-written AGENTS.md but no akrctx install
mkdir /tmp/test-repo && cd /tmp/test-repo
echo "# My custom agent instructions" > AGENTS.md

# Run doctor
cd /Users/alex/akrcontext && pnpm akrctx doctor --cwd /tmp/test-repo

# Should NOT report Codex as installed
```

## Out Of Scope

- Retroactively marking existing hand-written files
- Changing the readiness score calculation beyond fixing this detection

## Acceptance Criteria

- [ ] Hand-written `AGENTS.md` doesn't trigger false positive
- [ ] Actual akrctx-installed Codex target still detected correctly
- [ ] All existing tests pass
- [ ] Edge case: akrctx-installed `AGENTS.md` that was manually modified is still handled sensibly

## Clarifications

### Session 2026-08-18

- Detection reads **provenance from `.akrctx/manifest.json`** (Option A). No marker comment, no
  content hash as the primary signal.
- An install made before the manifest existed is reported as **not installed**, with a message
  telling the user to re-run `init`. One rule, no guessing. The cost is real and accepted: a user
  whose install works will suddenly see doctor say otherwise and will have to act. A fallback to
  the old check would reintroduce the exact false positive this capsule fixes, for every repository
  without a manifest — which trades a visible inconvenience for an invisible wrong answer.
- The message must say what to run and that re-running `init` preserves their instruction files.
  A user told they are not installed, when they are, will assume the tool is broken unless the
  message explains itself.
- A file listed in the manifest whose **hash no longer matches is still installed**. akrctx's own
  policy is `preserve-and-suggest`, so a user editing their `CLAUDE.md` is doing what the harness
  invites. Reporting that as uninstalled would punish the intended workflow and affect far more
  users than the bug being fixed.
- The fix covers **all three targets**, not only Codex. `presence.some(Boolean)` over
  `targetRequired[target]` has the same defect for `CLAUDE.md` and
  `.github/copilot-instructions.md`.

## Open Questions

- Should `doctor --fix` offer to write a manifest for a pre-existing install? It would turn the
  message above into a one-command fix. It is not in this capsule because `--fix` would have to
  hash the existing files and decide what to record for ones the user has edited, and that is a
  design question about provenance, not a detection fix.
