# Review Checklist

## The contract per surface was decided first

- [ ] `log.md` records, for each of the six surfaces, what the CLI prints and which part of it is
      the contract. Not every surface deserves byte-level strictness.
- [ ] `log.md` records which surfaces vary between runs on the same tree, and how each is handled.

## Every scenario can actually fail

- [ ] For **each** scenario individually: a deliberate one-character output change makes it fail,
      and the transcript is in `log.md`. Not once for the suite — once per scenario.
- [ ] Each scenario was run twice on the same ref and agreed with itself.
- [ ] No scenario depends on a timestamp, a host path, or a build-output hash.
- [ ] `pnpm eval:compare` reports every new scenario as `preserved` against an unchanged tree.

## Coverage matches the six capsules

- [ ] doctor gap messages, including the config and policy text TASK-026 must not change.
- [ ] Hook trace report, including the uncertainty flag TASK-027 must preserve.
- [ ] Judge snapshot exclusion and hook blocked-path flagging, for TASK-029.
- [ ] Content generated by `init` and `upgrade`, including the project name, for TASK-033.
- [ ] `init`, `doctor`, `doctor --json`, `doctor --ci`, `templates apply`, for TASK-034.
- [ ] All eight `judge` subcommands, human and `--json`, for TASK-035.
- [ ] The `verify` and `current` **failure** paths are covered, not only the success paths.
- [ ] `--json` surfaces are pinned as bytes where the schema allows; where it does not, the limit
      is recorded rather than quietly accepted.
- [ ] Each scenario's `hypothesis` names the capsule it protects.

## The six capsules were updated correctly

- [ ] All six `acceptance-criteria.md` files cite the gate.
- [ ] The manual capture procedures the gate replaces are **deleted**, not left alongside.
- [ ] Every surviving manual step carries one sentence saying why the gate does not reach it.
- [ ] No property lost its check. For each removed manual step, confirm a scenario covers the same
      property — this is the box where a capsule can be made to look more rigorous while being
      less checked.

## Nothing else moved

- [ ] No change to `evals/lib/`, `evals/schema/`, `evals/cli.mjs` or the fixtures machinery.
- [ ] No change to `src/`. Any bug a scenario revealed is a reported finding with its own capsule,
      not a fix smuggled in here.
- [ ] The `smoke` suite is unchanged and still passes.
- [ ] `pnpm eval` with no suite argument behaves as before.
- [ ] Existing fixtures were reused where possible rather than duplicated.

## Documentation

- [ ] `evals/README.md` documents the gate: exact command, when to run it, what `preserved` versus
      `inconclusive` means for a refactor.
- [ ] The Refactor row of the "Minimum evidence" table names the command.

## Validation

- [ ] `pnpm lint && pnpm build && npx vitest run` passes, output recorded verbatim in `log.md`.
- [ ] `pnpm lint` reports zero errors and zero warnings.
- [ ] `pnpm eval -- --suite refactor` passes.
- [ ] `pnpm eval:compare -- --base origin/main --candidate HEAD --suite refactor` reports every
      scenario `preserved`, report recorded in `log.md`.
- [ ] No test skipped to make the suite green.
- [ ] No Biome rule disabled, inline-ignored, or downgraded to reach a clean run.
- [ ] `CHANGELOG.md` purely additive, continuations indented two spaces.
