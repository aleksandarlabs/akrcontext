# Acceptance Criteria

## Evidence binding

- [ ] `verifyJudgeRecord` reads the commands a capsule declares in a fenced block
      under `## Validation` in `task.md` and exposes them as `declaredCommands`.
- [ ] When a capsule declares commands, an APPROVED record must claim at least one of
      them as `passed`. A record backed only by an invented command is rejected.
- [ ] When a capsule declares none, the weaker TASK-002 rule stands and the record is
      not blocked, so existing capsules keep verifying.
- [ ] `akrctx judge verify --run-tests` re-executes the capsule-declared commands the
      record claims passed, and fails verification when one of them actually fails.
- [ ] `--run-tests` never executes a command that appears only in the review record.
      A record naming an undeclared command produces no execution at all.
- [ ] Capsules generated by `akrctx task` and the shipped `_template` include a
      `## Validation` section, so the rule has something to bind to.

## Blocked paths

- [ ] Paths matching `blockedReadPatterns` are excluded from the diff at the Git level,
      for tracked and untracked files alike, and never read or hashed.
- [ ] Excluded paths appear in `scope.excludedPaths` by path only.
- [ ] Rotating a blocked file's contents inside the boundary does not change
      `changeDigest`.
- [ ] A blocked path entering or leaving the boundary does change the scope and
      invalidates a stale approval.
- [ ] An untracked blocked file no longer aborts scope computation.

## Provenance

- [ ] `scope.cliVersion` records the akrctx version that computed the boundary.
- [ ] A record whose `cliVersion` differs from the running CLI fails verification with
      a message naming both versions.
- [ ] The contract is `akrctx-judge-review-v2`; `schemaVersion` is 2 in both the record
      and the scope, and `requireJudgeContract` checks the v2 identity.
- [ ] A record still declaring `schemaVersion: 1` is rejected.

## Contract and docs

- [ ] `review.schema.json` requires `cliVersion` and `excludedPaths`.
- [ ] The generated judge instructions cover the declared-command rule, the withheld
      paths, and that the caller can re-run the commands.
- [ ] `docs/JUDGE.md` and the shipped `.akrctx/judge/README.md` state plainly what a
      verified record does and does not prove.
- [ ] `.akrctx/judge/**` and `.claude/agents/akrctx-judge.md` regenerated through the
      upgrade path, not hand-edited, and matching `.akrctx/manifest.json`.
- [ ] `pnpm test` passes.
- [ ] `pnpm lint` passes at the repository root.
