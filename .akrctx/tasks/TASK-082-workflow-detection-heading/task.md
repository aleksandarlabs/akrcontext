# TASK-082 — Read the workflow from where capsules record it

## Goal
Make `akrctx task show` report the workflow a capsule actually declares. Today it reads a
heading that almost no capsule uses, so it reports no workflow for most of them.

## Problem evidence
`showTask` in `src/task.ts` extracts the workflow with
`/## Recommended Workflow\n\n(.+)/` applied to `task.md`. Only `akrctx task create` writes that
heading, and only 17 of 80 capsules contain it.

Every recent capsule records the workflow in `plan.md` under `## Workflow`, which is what the
shipped `_template/plan.md` ships and what 79 of 80 capsules use. The result:

```
TASK-071 workflow=None
TASK-072 workflow=None
TASK-073 workflow=None
TASK-074 workflow=None
TASK-075 workflow=None
```

Those five capsules all declare a workflow and a reason in `plan.md`. `config.json` sets
`defaults.requireWorkflowReason: true`, and `policy.json` sets
`enforcement.requireWorkflowReason: true`, yet the one read surface that reports the workflow
cannot see it. Anything built on `akrctx task show --json` inherits the blind spot.

## Contract

- Read a declared workflow from plan.md under `## Workflow` first, accepting prose and bullet
  forms. Normalize surrounding whitespace, a single bullet marker and a terminal sentence
  period so existing `TDD.` and `fast-patch.` declarations return their workflow value.
- If that section has no value, fall back to task.md's `## Recommended Workflow`. A non-empty
  plan declaration wins when the two disagree.
- Report the declared string; do not reject unknown values or compare against allowedWorkflows.
  `UI review` remains readable even though it is not a user-selectable default.
- With no declaration in either location, leave workflow absent. Do not infer a recommendation.
- Keep the JSON shape and generated capsule layout unchanged. Reason extraction, declaration
  enforcement and removing the legacy generated heading are separate work.

## Validation
```
pnpm build
pnpm test
pnpm lint

```

## Out Of Scope

- Enforcing a workflow declaration or validating it against allowedWorkflows.
- Returning workflow reasons or changing the JSON shape.
- Rewriting existing capsules or changing the headings generated by task create.
- Changing available workflows or selectWorkflow recommendations.
